# Coding standards (what reviewers enforce)

Last updated 2026-11-11 (working tree on top of `c6e855b`). Architecture and rationale: [docs/architecture.md](docs/architecture.md), [docs/wiki/index.md](docs/wiki/index.md). Rules marked **[lint]** are enforced by `npm run lint`; **[test]** by a test; the rest by review.

## 1. The rights rule (highest priority)

1. No file is readable, downloadable or listed unless `src/lib/policy` (`canList`, `canRead`, `canDownload`, `canPublish`) says so. Never decide access with an ad-hoc `if (book.status === "published")`. Pages, route handlers, search, sitemap, JSON-LD, OG images and file streams all go through the policy (directly or via a service that does).
2. Public book queries use the single `publicBookPredicate()` from the catalogue repository (S2). Do not write your own `WHERE status = 'published'`.
3. Defaults are deny: a new book is `draft`, a new licence is `pending` with `allow_read=false`, `allow_download=false`. Never add a seed, fixture or migration that creates book, author, licence or asset rows. Test rows come from `tests/helpers/factories.ts` in throwaway databases only.
4. Never invent licence data, rights holders, ISBNs or statistics. Sample content is generated by the repo with licence type `project-original`.
5. File responses use `Cache-Control: private, max-age=0, must-revalidate` (never `public`). Signed URLs are never stored, logged or rendered into HTML; TTL <= 60 s.
6. Any change to rights or publish state writes an `audit_log` row in the same transaction.

## 2. Layering **[lint]**

```
app (pages, route handlers)  ->  services  ->  repositories  ->  db
components / lib / contracts : pure; may not import src/server, DB drivers, fs, child_process, node:crypto, or src/lib/env
```

- `src/app/**` may not import `@/server/db`, `@/server/repositories`, `drizzle-orm`, `pg`, PGlite, or `child_process`.
- Only `src/server/db`, `src/server/repositories` (and `src/server/auth/rate-limit.ts`) import the Drizzle schema or `drizzle-orm`.
- Every `src/server/**` entry module starts with `import "server-only"`. Internals that scripts/tests import directly may omit it.
- Only repositories touch tables. Services orchestrate; they never build SQL.
- `src/contracts` is frozen after S1 except by explicit orchestrator decision.

## 3. TypeScript and safety

- `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noImplicitReturns`. No `any` **[lint]**, no non-null `!` outside tests **[lint]**, no unexplained `as` casts (prefer a zod parse or a type guard).
- `@typescript-eslint/no-floating-promises` and `no-misused-promises` **[lint]**. Await or `void` deliberately.
- `eqeqeq`; `no-console` except `warn`/`error` **[lint]**; no `eval`, `new Function`, implied eval **[lint]**.
- Parse every boundary with zod: route inputs, search params, form data, env, CSV rows, localStorage. Define schemas once in `src/contracts`; do not duplicate them in components.
- Read environment only through `getEnv()` in `src/lib/env.ts` **[lint]** (`process.env` is allowed only there, in config files, scripts and tests). Never log or return an env value, a connection string, a token or a password hash. Error messages carry variable names only.
- Database enums come from `src/contracts/enums.ts`; do not hand-copy string unions.
- Prefer pure functions with an injected clock (`now: Date`) and injected I/O so they are unit-testable.

## 4. Security patterns

- No `dangerouslySetInnerHTML` **[lint]**. The single allow-listed file is `src/components/seo/JsonLd.tsx` (JSON-LD), which must serialise with `JSON.stringify` and escape `<`.
- No `sql.raw` and no string-built SQL outside `src/server/db`, `src/server/repositories`, scripts and tests **[lint]**. Use Drizzle's `sql` template with parameters.
- External URLs supplied by operators go through `validateExternalUrl` (https only, no credentials, no private/loopback/link-local/metadata addresses). Anything that later *fetches* such a URL must re-check every resolved IP with `classifyIp` and connect to that address.
- Storage keys are opaque and server-generated (`assetStorageKey`); never build a key or path from user input. The local driver additionally rejects traversal and symlinks.
- Uploads: verify size, `%PDF-` header and sha256 server-side; never trust a client-declared type. Run pdf.js client-side only, on files that passed upload validation.
- Mutating requests check `Origin`; admin cookies are `HttpOnly`, `Secure`, `SameSite=Strict`. Raw client IPs are never stored (salted, rotating hash only).
- Never commit secrets. `.env*` is gitignored; only `.env.example` with placeholders is tracked.

## 5. Database and migrations

- Change the Drizzle schema, run `npm run db:generate`, commit the generated SQL in `drizzle/`. Never edit an already-committed migration; add a new one. Triggers, extensions and functions use `drizzle-kit generate --custom`.
- `next build` must never open the database. PGlite is one process per data directory: do not run a script and the dev server on the same `PGLITE_DATA_DIR`.
- Every new table gets: uuid pk (`gen_random_uuid()`), `created_at`/`updated_at` unless append-only, foreign keys with an explicit `onDelete`, indexes for every FK used in a filter, and CHECK constraints for invariants the app relies on.

## 6. React, routing, UI

- Server Components by default. Add `"use client"` only for interactivity, and keep client components free of server imports **[lint]**. `pdfjs-dist` is imported dynamically in a client component only.
- Components in `src/components/ui` are the only place raw colours/spacing live; everything else uses design tokens.
- Accessibility: semantic landmarks, visible `:focus-visible`, labelled controls, `alt` text, no emoji as the only icon, respect `prefers-reduced-motion`. `jsx-a11y` rules are errors **[lint]**; axe runs in e2e.
- GSAP is allowed on the marketing homepage only, scoped with `gsap.context` and cleaned up.

## 6a. Style

- Name by domain meaning; no abbreviations that need a glossary. Keep modules small and single-purpose. Comments explain *why*, not *what*.
- Import order: node builtins, packages, `@/` aliases, relative. Use `import type` / inline `type` for type-only imports **[lint]**.
- No dead code, no commented-out code, no TODO without an owner and a stage reference.

## 7. Tests

- `npm run verify` must pass before a stage is done: environment check, lint, typecheck, unit and integration tests. `npm run build` is run separately (it is slow and writes `.next`). `npm run e2e` needs a production build and `npx playwright install chromium`.
- Every pure module has table-driven unit tests; `src/lib/policy/index.ts` keeps 100% branch coverage (`npm run test:coverage` fails below it) **[test]**.
- Integration tests create their own in-memory PGlite (`tests/helpers/db.ts`) and never share state between files. Storage drivers pass the shared contract suite (`tests/helpers/storage-contract.ts`).
- Test PDFs are generated by `tests/helpers/pdf-fixtures.ts` from original text. Do not commit third-party PDFs, covers or text.
- A bug fix lands with a test that fails without it.

## 8. Dependencies

- Pin risky libraries exactly (`pdfjs-dist`, `drizzle-orm`, `drizzle-kit`, `@electric-sql/pglite`, `vitest`, `zod`, AWS SDK). Add dependencies only in S1 or via the orchestrator; justify each in the wiki.
- Run `npm ci`, not `npm install`, to reproduce the lockfile. `npm run check:env` explains drift.

## 9. Documentation

- Every claim in `docs/wiki` carries a date and cites a commit (or "working tree on top of `<hash>`"). Add or update a wiki page for any decision and update `docs/wiki/index.md`.
- No marketing claims (statistics, user counts, testimonials) without a query that produces them.
