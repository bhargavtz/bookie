# Decision: testing strategy

Date: 2026-11-11. Status: accepted (proposal confirmed with changes). Baseline `c6e855b` has no tests and no test runner (2026-11-11). Related: [database](decision-database.md), [storage](decision-storage.md), [rights enforcement](decision-rights-enforcement.md), [toolchain](decision-toolchain.md), [architecture](../architecture.md).

## Decision

- Unit and integration: Vitest 5.1.0 with `@vitest/coverage-v8`. Requires Node `^22.12 || ^24 || >=26` (npm metadata, 2026-11-11) and `@types/node` >=22. Projects: `unit` (node), `integration` (node, PGlite in memory plus local storage in a temp dir), `components` (jsdom 31 and `@testing-library/react` 16.3.3, only where needed).
- DB tests: `createTestDb()` makes a fresh in-memory PGlite per test file and applies the committed migrations; cache a loaded data-dir snapshot if startup cost matters. No Testcontainers (no Docker on the audit machine, 2026-11-11).
- Storage tests: one shared contract suite run against the local driver always, and against S3 only when `S3_TEST_ENDPOINT` is set.
- e2e: `@playwright/test` 1.65.0 plus `@axe-core/playwright` 4.14.0; axe on every page type fails on serious/critical; Chromium only at first; `workers: 1` because PGlite is single-process; the web server command prepares a dedicated data dir (migrate and generate sample books) before `next start`. `npx playwright install chromium` is needed on fresh machines; browser caches for three Chromium builds existed on the audit machine (2026-11-11) but the required build for 1.65 is unconfirmed.
- Validation: `zod` 4.6.7 at every boundary (route inputs, env, CSV rows, localStorage). Hand-written schemas; do not add `drizzle-zod`.
- Test PDFs: generated by `scripts/gen-test-pdfs.ts`, a small dependency-free deterministic PDF writer (multi-page, selectable text, optional outline, unique text per book for search tests); output under gitignored `tests/fixtures/generated/`. Removes any third-party licensing question. `pdf-lib` 1.17.1 is a fallback.
- Coverage targets: 100% branch on `src/lib/policy`, high on range parsing, search parsing, CSV parsing, auth.
- Mandatory suites: rights matrix, route inventory, DB trigger, range requests, rate limiting, session expiry, import duplicate handling.

## Risks (2026-11-11)

Playwright browser install needs network; PGlite and Next bundling must be proven in S1 ([database](decision-database.md)); Vitest 5 is a very recent major, pin and re-run on upgrade; flaky e2e from animation, so disable GSAP motion under `prefers-reduced-motion` and in test mode.

## Update 2026-11-11 (S1 implemented; working tree on top of `c6e855b`)

Implemented: Vitest 5.1.0 with projects `unit` (`tests/unit/**`) and `integration` (`tests/integration/**`); the `components` project is deferred until a stage needs jsdom. `npm test` is `vitest run --configLoader runner` (the default native config loader warns about ESM syntax in a CommonJS package) and has a `pretest` that writes PDFs to `tests/fixtures/generated/`. `npm run test:coverage` enforces 100% branch/line/function/statement coverage on `src/lib/policy/index.ts`. `tests/helpers/db.ts` gives each test file its own in-memory PGlite with all migrations applied (about 1 to 2 s start-up per file). `tests/helpers/pdf-writer.ts` and `pdf-fixtures.ts` generate four deterministic PDFs (searchable 2 pages, multipage 24, restricted 3, corrupt = valid header plus junk) from original text and a manifest of hashes; a unit test loads them with `pdfjs-dist` 6.5.438 and asserts page counts and extractable text, and that the corrupt one fails. Storage drivers share `tests/helpers/storage-contract.ts`; the S3 run uses an in-process fake (`tests/helpers/fake-s3.ts`) and a real endpoint when `S3_TEST_ENDPOINT` and `S3_TEST_BUCKET` are set. Playwright: `playwright.config.ts` (webServer resets `.data/e2e`, runs `db:setup`, then `next start -p 3100`; projects `desktop` and `mobile`, one worker) loads, but there are no e2e tests until S7 and Chromium for 1.65.0 was not confirmed installed. Playwright runs against a production build, so run `npm run build` first.
