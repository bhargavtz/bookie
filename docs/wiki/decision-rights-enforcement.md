# Decision: rights enforcement

Date: 2026-11-11. Status: accepted (new). Baseline `c6e855b` has no books, licences or enforcement (2026-11-11). Related: [storage](decision-storage.md), [admin auth](decision-admin-auth.md), [reader and state](decision-reader-and-state.md), [database](decision-database.md), [audit](audit-2026-11-11.md), [architecture](../architecture.md).

## Principle

Nothing is public until a human with the right role records rights evidence. The reference site observed on 2026-11-11 shows no licence or takedown information while offering well-known commercial titles ([audit](audit-2026-11-11.md) section 7); Bookie does the opposite: default deny.

## Decision

1. One pure module `src/lib/policy/` exports `canList`, `canRead`, `canDownload`, `canPublish`, each returning `{allowed}` or `{allowed:false, reason, httpStatus}`. Every page, route handler, search query, sitemap, JSON-LD and OG generator uses it (directly or via a service). Admin preview is separate and cannot count downloads.
2. `licenses.rights_status` is `pending` (default), `approved`, `restricted` or `removed`; `allow_read` and `allow_download` default false; `restricted` forbids download; `expires_at` in the past is treated as `pending`.
3. Public behaviour table: pending/none/expired = hidden (404); approved = listed, read if `allow_read`, download if `allow_download`; restricted = listed, read-only; removed = 410 tombstone without title or cover. Additional requirements: book `published`, not soft-deleted, primary PDF `ready`.
4. Publishing requires rights holder, licence type, evidence, approver and timestamp, a `ready` PDF with sha256, and resolution of duplicate flags. Approving rights requires role `owner` or `reviewer`; `editor` cannot.
5. Defence in depth: a database trigger blocks `books.status='published'` without an approved or restricted licence; public queries use one `publicBookPredicate()` fragment; ESLint forbids table access outside repositories.
6. Takedown: public form writes `takedown_requests`; an admin "Remove" action is one transaction (licence removed, book unpublished, audit row, optional object purge). File responses use `Cache-Control: private, max-age=0, must-revalidate` so removal is immediate.
7. Sample/demo content is generated by the repo with licence type `project-original`; nothing else is imported without evidence.

## Verification plan

Static route-inventory test, rights matrix integration test (one book per state against every public surface), trigger test, and 100% branch coverage on `src/lib/policy/`.

## Open items

Legal text (terms, privacy, takedown wording) needs human legal review; this wiki is not legal advice (2026-11-11).

## Update 2026-11-11 (S1 implemented; working tree on top of `c6e855b`)

`src/lib/policy/` is implemented with 100% branch coverage and a table-driven matrix (public and admin viewers; every licence state, book status, deletion, expiry and asset state). The DB guard is in migration `0002`: an immediate `BEFORE INSERT OR UPDATE` trigger on `books` and a deferred constraint trigger on `licenses` (so "remove licence + unpublish" works in one transaction and a half-done change fails at commit). Details, check order and the extra licence CHECK constraints are in [stage-s1-foundation](stage-s1-foundation.md). Still to build by later stages: `publicBookPredicate()` (S2), the static route-inventory test and the all-surfaces rights matrix (need routes to exist; S7), `audit_log` writes (S5a).
