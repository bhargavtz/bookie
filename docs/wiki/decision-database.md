# Decision: database (PostgreSQL, Drizzle, PGlite)

Date: 2026-11-11. Status: accepted (proposal confirmed with changes). Baseline `c6e855b` has no database or ORM (2026-11-11). Related: [storage](decision-storage.md), [testing](decision-testing.md), [toolchain](decision-toolchain.md), [architecture](../architecture.md), [audit](audit-2026-11-11.md).

## Decision

- PostgreSQL is the system of record. Schema in Drizzle ORM (`drizzle-orm` 0.45.4, `drizzle-kit` 0.31.11, both `latest` on npm 2026-11-11; `drizzle-orm` 1.0 exists only as beta/rc tags on that date, so it is not adopted).
- Production driver: `pg` (node-postgres) 8.23.1 via `DATABASE_URL`. Changed from the "postgres or node-postgres" proposal: pick one; `pg` has the widest hosting/TLS/pooler behaviour and Drizzle's primary support. Do not add `postgres` (postgres.js) as well.
- Local dev and automated tests: `@electric-sql/pglite` 0.5.16 with the Drizzle `pglite` driver, so no external database is needed. Data dir `.data/pglite` for dev, in-memory per test file.
- One migration folder `drizzle/` generated by drizzle-kit and applied by the matching migrator (`drizzle-orm/node-postgres/migrator` or `drizzle-orm/pglite/migrator`). Generated tsvector columns, triggers and `CREATE EXTENSION` live in hand-written custom migrations (`drizzle-kit generate --custom`).
- Search: Postgres full-text (weighted generated `tsvector` + GIN) plus `pg_trgm` for typo tolerance and `unaccent`.

## Evidence (verified 2026-11-11)

Scratch experiment outside the repo with `@electric-sql/pglite@0.5.16`, extensions `pg_trgm` and `unaccent` loaded from `@electric-sql/pglite/contrib/*`:
- `select version()` returned PostgreSQL 18.6 (PGlite 0.5.16, wasm32).
- A table with a `GENERATED ALWAYS AS (setweight(to_tsvector(...),'A') || setweight(...,'B')) STORED` column, a GIN index on it, and a `gin_trgm_ops` GIN index on `title` were created.
- `websearch_to_tsquery('english','algorithm')` matched "Introduction to Algorithms" with `ts_rank` 0.608.
- `similarity(title,'algoritms')` (typo) returned 0.276 and matched via trigram.
- `unaccent('Café')` returned `Cafe`; `gen_random_uuid()` works.
So FTS and trigram search behave as in server Postgres for our use.

## Constraints and mitigations

1. Single process, single connection. Never open one data directory from two processes (dev server plus a seed script, Playwright server plus Vitest). Seed/migrate scripts run before the server starts or inside it. Playwright uses its own dir and `workers: 1`.
2. `next build` must not query the database (all DB-backed routes are dynamic) because build workers are separate processes.
3. Next HMR: create the client once on `globalThis`.
4. Bundling: needs `serverExternalPackages: ['@electric-sql/pglite']`; confirm under Turbopack dev, webpack build and `next start` in the S1 spike before dependent work starts.
5. Parity: PGlite runs PostgreSQL 18; require production Postgres >=16 (recommend 17+). Run the integration suite against a real server when `DATABASE_URL` is provided (not possible on the audit machine, which has no Docker, 2026-11-11).
6. `CREATE EXTENSION pg_trgm, unaccent` needs privileges on managed hosts; both are standard "trusted" contrib extensions on modern PostgreSQL, verify per provider.
7. Postgres FTS tokenises `c++`, `c#`, `.net`, `node.js` poorly. Use a `technologies` table with aliases and expand queries; see [architecture](../architecture.md) section 4.5.
8. Type friction: pg and pglite Drizzle databases share the `PgDatabase` base type but differ in result types. Repositories take one `Db` alias exported from `src/server/db`.
9. Memory: PGlite is 32-bit WASM; fine for dev/test data volumes, not a production option.

## Alternatives considered

SQLite (libsql) would be simpler locally but loses identical FTS/trigram behaviour in production. Prisma adds a generated client and a heavier toolchain with no PGlite parity advantage. Postgres.js alone: fine, but fewer tools assume it.

## Update 2026-11-11 (S1 implemented; working tree on top of `c6e855b`)

Implemented as decided; see [stage-s1-foundation](stage-s1-foundation.md) for specifics. Notes: (1) the FTS generated column cannot read authors/tags, so a maintained `books.search_text` column feeds weight B; (2) `unaccent()` is STABLE and is wrapped in an IMMUTABLE `bookie_unaccent()` function (migration `0000`); (3) typo search should use `word_similarity`/`<%`, because `similarity()` scored 0.28 for a typo against a long title; (4) PGlite works under `next build`, `next start` and `next dev --turbopack` with `serverExternalPackages` (verified 2026-11-11), with the client held on `globalThis`; (5) the Drizzle `Db` alias is `PgDatabase<PgQueryResultHKT, Schema>` and both drivers are cast to it in `src/server/db/client.ts`; (6) migrations: `0000` extensions/function (custom), `0001` schema (generated), `0002` triggers (custom); apply with `npm run db:migrate`; real-PostgreSQL parity remains untested (no Docker, 2026-11-11).
